# Investigation

**Read-only. Answer from evidence. Change nothing.**

1. Load the `how` skill for how something works or where it lives. Add the `why` skill for motivation and history ("why is it like this", "can we delete this").
2. For "are we sure?" questions, push back when the premise is wrong.
3. Label each claim measured, inferred or guess. Never hand the user a check you could run.
4. If the answer leads to a code change, stop and route that change with the user.

**Reply:** overview, key concepts, how it works, where things live (file paths), gotchas. Or a recommendation with a trade-offs table.
